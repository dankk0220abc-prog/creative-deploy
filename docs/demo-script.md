# CreativeDeploy portfolio demo script

**Duration:** 2–4 minutes. **Mode:** local synthetic/Fixture, Live OFF, Provider calls = 0. Do not enter a credential, use a private image, or invoke a live provider.

## 0:00–0:20 — Set the frame

> CreativeDeploy is one Browser-first AI application platform with two intentionally different products: PaintPilot for governed visual-workflow planning and Arcana for question-aware reflective readings. I wanted to show that the AI surface and the governance surface have to be designed together.

**Shot:** product chooser at `http://127.0.0.1:18173/` after synthetic sign-in.

## 0:20–1:20 — PaintPilot

Open **PaintPilot** → preloaded synthetic project → ImageSet/RegionSet workspace.

> A paint plan is not just model prose. The project keeps private image roles, immutable versions, readiness review and human-authored region geometry. The eventual plan is structured, source-aware and reviewable; human approval remains a separate state.

Point to the synthetic banner, image-role history, region workspace, plan/citation surface where available, and a safe provider/audit view. Say: “The real GLM-5V-Turbo path was independently proven, but this demo intentionally stays offline and repeatable.”

## 1:20–2:30 — Arcana

Open **Arcana** → **打开 Fixture 解读** → the preloaded question `我九月份会有正缘吗` → interpretation → Journal/history.

> The first version could explain individual cards but did not answer the question. V2 analyzes domain and temporal frame, combines card position and orientation with deterministic cross-card relationships, retrieves compact local knowledge, and produces a cited, schema-governed synthesis. The Future position is a tendency, not a guarantee.

Show the three-card layout, question-aware interpretation, citations, and the fact that a Journal note is separate from the immutable draw. The public profile is deliberately read-only; do not attempt to create a new reading during the demo.

## 2:30–3:20 — Platform governance

> Both products reuse the platform’s authorization, policy, encrypted BYOK boundary, accounting and audit structure. Before dispatch, a request has to pass policy, budget reservation and a durable pre-egress claim. That is why retries, concurrency and provider outcomes can be accounted for honestly.

**Shot:** [architecture diagram](architecture.md#governed-provider-invocation-flow) or a safe UI status surface. Do not show secrets, raw payloads or private data.

## 3:20–end — Close honestly

> The value is not claiming a public SaaS. It is showing two distinct AI products on a reusable governed platform, with real-provider proof where authorized and a local-first demo that anyone can run without a key.
