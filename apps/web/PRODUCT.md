# PaintPilot Product Context

## Product world

PaintPilot is CreativeDeploy's image-first operational workbench for governed paint-planning records. It is a restrained, dark, technical workspace rather than a marketing site. The incumbent Projects, private ImageSet, human readiness, and Polygon RegionSet flows remain the visual and interaction authority.

## Phase 3A visual brief

The BYOK Multi-Provider Foundation First Slice adds platform settings for Models & Providers, Credentials, and Usage & Audit, plus a project-scoped AI Model Policy surface. It is fixture-only, local-only, development/test-only, and must make those constraints obvious without overwhelming the working controls.

The visual direction is a compact operations console within the existing PaintPilot shell:

- dark graphite surfaces, warm off-white type, copper action accent, teal safe/local signal, and gold synthetic-budget values;
- rectangular registry rows, metric strips, explicit identifiers, labeled statuses, and restrained borders;
- a clear hierarchy from platform registry to user route to project policy;
- no gradients, hero marketing composition, bento showcase, decorative carousel, excessive pills, or fake provider logos;
- no invented live network state, real cost, real provider choice, or completed invocation result.

## Interaction contract

Credential inputs use password controls, are never echoed into results, and are cleared after save/error. Saving requires a successful local fixture validation plus explicit encrypted-storage confirmation. Revocation is named as cryptographic erase. Project policy requires an active exact credential grant and keeps manual model IDs, fallback, and unknown cost visibly blocked.

Desktop is information-dense but readable. At 720px and below, columns become a single working stack. At 430px and 390px, secret fields and destructive controls remain single-column, labels remain visible, identifiers wrap, and all interactive controls retain usable touch targets. Status is always communicated in text, not color alone.

## Release boundary

Phase 3A First Slice performs no real provider call, has no custom provider URL, has no real monetary currency, and provides no production or staging enablement. The feature is hidden in the web application unless `VITE_PHASE3A_FIXTURE_ENABLED=true`; the API separately fails closed unless its own development/test fixture gate and binary root-key file are valid.
